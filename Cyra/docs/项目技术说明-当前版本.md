# Cyra 灵山胜境 AI 数字人导览系统技术说明

本文档用于帮助组员快速了解当前项目已经实现的内容、技术栈、运行方式和后续开发入口。当前版本面向中国软件杯赛题“AI 数字人景区导览系统”，以灵山胜境官方资料包为主要知识来源。

## 1. 当前实现概览

项目目前已经从早期数字人 Demo 改造成一个包含游客端、管理端和后端服务的比赛原型。

已实现：

- 演示入口页：`http://127.0.0.1:5173/`
- 游客端数字人导游：`http://127.0.0.1:5173/tourist.html`
- 园区管理后台：`http://127.0.0.1:5173/admin.html`
- FastAPI 后端：`http://127.0.0.1:8001`
- 官方资源包解析：读取 Word 景点资料和 Excel 行为数据。
- 本地知识库检索：游客提问前先检索官方资料包，再生成回答。
- 数字人播报：TTS 音频播放时驱动口型和说话状态。
- 语音输入：浏览器录音后通过 WebSocket 接入 ASR。
- 游客反馈闭环：游客端评论/满意度反馈会进入后台报告统计。

## 2. 技术栈

### 后端

- Python
- FastAPI：后端 API 服务
- Uvicorn：本地后端运行服务器
- Pydantic / pydantic-settings：请求模型和配置管理
- httpx：调用大模型兼容接口
- websockets：连接阿里云 NLS ASR/TTS WebSocket 服务
- python-docx：解析官方 Word 资料包
- openpyxl：解析官方 Excel 游客行为数据

### 前端

- 原生 HTML / CSS / JavaScript
- 浏览器 Web Audio API：录音、音频分析、口型同步
- localStorage：游客端本地评论缓存
- Fetch API：调用后端 REST 接口
- WebSocket：语音识别实时音频流

### AI 与语音能力

- LLM：通义千问兼容接口，配置项为 `DASHSCOPE_API_KEY` 和 `DASHSCOPE_MODEL`
- ASR：阿里云 NLS 语音识别
- TTS：阿里云 NLS 语音合成
- 知识库：官方资料包本地检索，当前使用关键词检索，后续可升级向量检索

```text

```

- 后端：`http://127.0.0.1:8001`
- 前端：`http://127.0.0.1:5173`

## 5. 前端页面说明

### 演示入口页

文件：`src/frontend/index.html`

作用：

- 作为比赛演示首页。
- 提供游客端和管理端两个入口。
- 使用统一背景图和产品介绍文案。

### 游客端

文件：`src/frontend/tourist.html`

核心体验：

- 左侧为玄奘数字人主舞台。
- 右侧为对话区，打开即可输入问题或录音。
- 快捷景点按钮：例如灵山大佛、九龙灌浴、灵山梵宫、五印坛城等。
- 快捷路线按钮：历史文化、亲子家庭、自然风光。
- “游客热评”按钮打开评论抽屉，保留景点评论和反馈提交能力。

当前游客端重点优化方向：

- 主视觉突出数字人和对话。
- 评论功能保留，但作为辅助抽屉，不占首屏主位。
- 对话区内部滚动，避免内容过多导致数字人区域被挤压。

### 管理后台

文件：`src/frontend/admin.html`

已实现模块：

- 行为样本数
- 覆盖景区数
- 灵山相关访问量
- 平均满意度
- 平均停留时长
- 游客感受度报告
- 行业热门景区对比
- 游客年龄/性别画像
- 官方资料包知识库条目展示

## 6. 后端接口说明

### 基础接口

```text
GET /api/health
```

用于检查后端是否正常。

### 聊天接口

```text
POST /api/chat
POST /api/chat/stream
```

功能：

- 接收游客问题。
- 检索官方资料包知识库。
- 将资料上下文加入大模型提示词。
- 返回回答、会话历史和资料来源。

说明：

- 当前真实大模型请求失败时，会自动回退到资料包摘要回答，保证演示稳定。
- 流式接口用于游客端逐字/分段显示回答。

### 语音接口

```text
WebSocket /ws/asr
POST /api/tts
```

功能：

- `/ws/asr`：浏览器麦克风音频流转发给阿里云 NLS ASR。
- `/api/tts`：将文本合成为语音，前端播放时驱动口型同步。

### 知识库与游客端接口

```text
GET /api/knowledge/spots
GET /api/knowledge/search?q=关键词
GET /api/routes/recommend?interest=亲子家庭
POST /api/feedback
```

功能：

- 返回官方资料包里的景点列表。
- 搜索知识库。
- 根据兴趣推荐路线。
- 接收游客满意度和评论反馈。

### 管理后台接口

```text
GET /api/admin/knowledge
GET /api/admin/analytics/overview
GET /api/admin/analytics/report
PUT /api/admin/knowledge/{item_id}
```

功能：

- 查看官方资料包知识条目。
- 查看 Excel 行为数据统计。
- 生成游客感受度报告。
- 更新指定知识条目，支持演示“后台修改资料后影响回答”的方向。

## 7. 官方资源包使用方式

资料包目录：

```text
示范景区公开资料包/
```

当前使用方式：

- `灵山胜境 景点结构化数据集.docx`
  - 解析为景点主数据。
  - 用于游客端景点快捷按钮、景点摘要、景点评论初始内容。

- `灵山胜境：历史、文化、景点特色与个性化游览指南.docx`
  - 解析为长文本知识块。
  - 用于问答检索、路线推荐和讲解内容。

- `景点景区旅游数据行为分析数据.xlsx`
  - 解析为后台运营数据。
  - 用于游客画像、满意度、热门景区、消费结构和行业对比。

当前解析结果：

- 景点结构化条目：约 22 个
- 知识块：约 43 个
- 行为数据：约 140447 条
- 景区数量：约 152 个

## 8. 关键实现逻辑

### 问答流程

```text
游客输入问题
  -> 前端调用 /api/chat/stream
  -> 后端检索官方资料包
  -> 构造数字人人设 + 资料上下文
  -> 调用大模型
  -> 若大模型失败，则使用资料包摘要兜底
  -> 前端显示回答
  -> 调用 TTS
  -> 播放音频并驱动口型
```

### 游客反馈流程

```text
游客点击满意/一般/待改进，或提交景点评论
  -> 前端调用 /api/feedback
  -> 后端暂存在资源包服务内存中
  -> 管理后台报告显示实时反馈数量
```

说明：

- 当前反馈是轻量实现，适合比赛 Demo。
- 后续如需长期保存，应接入 SQLite 或其他数据库。

### 管理后台数据流程

```text
后台打开 admin.html
  -> 调用 /api/admin/analytics/overview
  -> 后端读取 Excel 并统计
  -> 前端渲染数据卡片、排行榜、画像和报告
```

## 9. 当前注意事项

### 不要上传真实密钥

`src/backend/.env` 可能包含真实 API Key。提交 GitHub 前必须确认：

- 不要提交真实 `.env`
- 可以提交 `.env.example`
- 如果 `.env` 已被 Git 追踪，需要先移除追踪

建议 `.gitignore` 包含：

```gitignore
.venv/
__pycache__/
*.pyc
*.runtime.log
*.runtime.err.log
src/backend/.env
.idea/
```

### 依赖问题

如果组员运行时报缺少：

- `python-docx`
- `openpyxl`

让他们执行：

```powershell
pip install -r requirements.txt
```

如果使用项目虚拟环境：

```powershell
& ".venv\Scripts\python.exe" -m pip install -r requirements.txt
```

### 手机扫码访问

手机不能访问 `127.0.0.1`。需要电脑和手机连接同一 Wi-Fi，然后用电脑局域网 IP：

```text
http://电脑IPv4地址:5173/tourist.html
```

例如：

```text
http://192.168.1.23:5173/tourist.html
```
