# Cyra 产品部署和使用手册

> **部署前必须确认：评委电脑已安装 64 位 Python 3.12，并且首次安装依赖时可以联网。**
>
> 本项目固定使用 Python 3.12，不支持用其他版本创建运行环境。推荐安装
> [Python 3.12.10（Windows 64 位）](https://www.python.org/downloads/release/python-31210/)，安装时勾选
> `Add python.exe to PATH`。项目不携带开发机的 `.venv`；评委运行一次 `安装环境.bat` 后，
> 脚本会在项目目录自动创建本机可用的 `.venv`。

## 1. 手册用途

本文档用于指导专家对 Cyra 景区 AI 数字人导览系统进行部署、访问和功能检查。

## 2. 验收说明

2.1语音服务、大模型 Key、测试资料和项目运行环境应由项目方提前准备好。专家只需要根据本手册进行功能验证。

## 3. 产品组成

Cyra 当前由以下模块组成：

- 游客端数字人导览页面
- 管理后台页面
- 知识库管理页面
- 数字人形象管理页面
- FastAPI 后端服务
- 本地 ChromaDB 知识库
- DashScope 大模型与向量模型服务
- 阿里云 DashScope CosyVoice 语音合成服务（默认主用）目前只限于四种音色：Cherry、Serena、Ethan、Chelsie
- 可选自部署 GPT-SoVITS 语音服务和 LAM 表情服务接入配置

## 5. 运行环境要求

### 5.1 必备环境（安装前确认）

- Windows 系统
- 64 位 Python 3.12（推荐 3.12.10）
- Chrome 或 Edge 浏览器
- 首次安装时网络可访问 PyPI
- 运行时网络可访问阿里云 DashScope 大模型和语音服务

在 PowerShell 中执行 `py -3.12 --version`，输出应以 `Python 3.12` 开头。如果提示找不到版本，请先安装 Python 3.12。

### 5.2 端口要求

系统默认使用：

- 后端端口：`8001`
- 前端端口：从 `5173` 开始自动寻找可用端口

如果端口被占用，需要先关闭旧服务，再重新启动。

## 6. 首次安装（自动创建 `.venv`）

解压项目后，双击项目根目录的 `安装环境.bat`。

脚本会自动检查 64 位 Python 3.12、清理损坏或版本不符的 `.venv`、创建新 `.venv`，并根据 `requirements.txt` 安装和检查全部依赖。看到“环境安装成功”后才算安装完成。

也可以在项目根目录的 PowerShell 中执行：

```powershell
py -3.12 setup_cyra_env.py
```

不要直接使用全局 `pip install`，也不要复制其他电脑生成的 `.venv`。首次安装需要联网，脚本可以安全地重复运行。

## 7. 配置文件说明

配置文件路径：

```text
src/backend/.env
```

专家验收前，项目方应提前配置好以下内容：

```env
APP_NAME=Cyra AI Guide
CORS_ORIGINS=["http://localhost:5173","http://127.0.0.1:5173"]

DASHSCOPE_API_KEY=由项目方提供
DASHSCOPE_MODEL=qwen3.7-plus
DASHSCOPE_API_URL=https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions
DASHSCOPE_EMBEDDING_MODEL=text-embedding-v4
DASHSCOPE_EMBEDDING_DIMENSION=1024

CHROMA_PERSIST_DIR=src/backend/chroma_db

TTS_PROVIDER=dashscope
DASHSCOPE_TTS_MODEL=cosyvoice-v3-flash
DASHSCOPE_TTS_VOICE=longanyang
DASHSCOPE_TTS_FORMAT=mp3
DASHSCOPE_TTS_SAMPLE_RATE=24000
DASHSCOPE_TTS_API_URL=https://dashscope.aliyuncs.com/api/v1/services/audio/tts/SpeechSynthesizer
DASHSCOPE_TTS_WS_URL=wss://dashscope.aliyuncs.com/api-ws/v1/inference

LAM_EXPRESSION_API_URL=
LAM_EXPRESSION_TIMEOUT_SECONDS=30

GPT_SOVITS_API_URL=http://127.0.0.1:9880
GPT_SOVITS_API_KEY=
GPT_SOVITS_REF_AUDIO_PATH=
GPT_SOVITS_PROMPT_TEXT=
GPT_SOVITS_PROMPT_LANG=zh
GPT_SOVITS_TEXT_LANG=zh
GPT_SOVITS_MEDIA_TYPE=wav
GPT_SOVITS_TIMEOUT_SECONDS=60

WHISPER_MODEL=base
WHISPER_LANGUAGE=Chinese
WHISPER_DEVICE=cpu
WHISPER_MAX_AUDIO_MB=20
```

说明：

- `DASHSCOPE_API_KEY` 用于大模型、图片理解和向量模型。
- `DASHSCOPE_MODEL` 当前使用 `qwen3.7-plus`。
- `DASHSCOPE_EMBEDDING_MODEL` 当前使用 `text-embedding-v4`，默认维度为 1024。
- `TTS_PROVIDER=dashscope` 是当前推荐和默认方案，系统使用同一个 DashScope API Key 调用阿里云 CosyVoice TTS。
- `TTS_PROVIDER=gpt_sovits` 是可选自定义方案，项目方可以自行部署 GPT-SoVITS 服务，并用自选样本训练或准备目标音色；配置参考音频、提示文本和服务地址后，Cyra 可调用该本地语音服务。若 GPT-SoVITS 调用失败，系统会回退到 DashScope TTS。
- `LAM_EXPRESSION_API_URL` 可选配置 LAM 表情服务。未配置时，系统会使用本地 ARKit 表情估算和音频能量口型方案。
- `WHISPER_*` 用于本地语音识别模型配置，默认使用 CPU 上的 `base` 模型。
- 专家不需要训练语音模型，只需要检查语音功能是否能正常使用。

## 8. 启动系统

双击项目根目录的 `启动Cyra.bat`。

启动器会直接打开并保持一个 Cyra 控制台窗口。请保持该窗口开启；前后端准备完成后，系统会通过 Windows 默认浏览器分别打开游客端和管理后台。关闭控制台或按 `Ctrl+C` 会停止服务。如果浏览器没有自动弹出，可复制控制台中显示的地址手动访问。

也可以在项目根目录的 PowerShell 中执行：

```powershell
.\.venv\Scripts\python.exe run_cyra_demo.py
```

脚本会自动启动：

- 后端服务
- 前端静态服务
- 游客端页面
- 管理后台页面
- 知识库管理页面
- 数字人形象管理页面（可从管理后台导航进入）

启动成功后，终端会显示类似地址：

```text
Tourist Live2D page: http://127.0.0.1:5173/tourist.html
Admin dashboard:     http://127.0.0.1:5173/admin.html
Knowledge manager:   http://127.0.0.1:5173/knowledge.html
Avatar manager:      http://127.0.0.1:5173/avatar.html
Backend health:      http://127.0.0.1:8001/api/health
```

如果 `5173` 被占用，前端可能会自动使用 `5174`、`5175` 等端口，以终端输出为准。

## 10. 语音服务验收说明

### 10.1 语音服务提供方式

本项目语音合成主链路默认使用阿里云 DashScope CosyVoice TTS。该方案只需要配置 DashScope API Key 和音色参数，不要求专家训练语音模型或准备参考音频。

项目同时保留 GPT-SoVITS 接入参数，作为可选的自部署语音服务方案。如果项目方希望使用自定义音色，可以自行部署 GPT-SoVITS，基于自选样本训练或准备目标音色，并将 `TTS_PROVIDER` 设置为 `gpt_sovits`。此时需要提前启动本地 GPT-SoVITS 服务，并配置参考音频、提示文本和服务地址。验收默认以 `.env` 中实际配置为准；未切换时按阿里云 CosyVoice TTS 验收。

专家只需要确认：

- 项目方提供的 DashScope API Key 已写入 `.env`
- Cyra 后端可以访问阿里云 DashScope，默认语音回复由阿里云 CosyVoice TTS 生成
- 游客端提问后，数字人可以播放语音回复
- 默认方案下，语音回复使用手册中配置的 CosyVoice 音色
- 如切换为 GPT-SoVITS，语音回复应使用项目方自部署服务中的训练音色或配置音色
- 如配置了 LAM 表情服务，检查口型和表情是否更自然；未配置时，只需检查基础口型联动是否存在

### 10.2 语音输入检查

操作步骤：

1. 打开游客端页面。
2. 点击输入栏旁边的麦克风按钮。
3. 对着麦克风说一句景区问题，例如“灵山大佛有什么特色”。
4. 再次点击麦克风结束录音。
5. 检查输入内容是否被识别并发送。

通过标准：

- 浏览器能正常请求麦克风权限。
- 录音结束后可以识别出文字。
- 识别结果会进入游客端问答流程。

### 10.3 语音回复检查

操作步骤：

1. 在游客端输入问题，例如“推荐一条适合亲子的路线”。
2. 等待数字人回复。
3. 检查是否有语音播放。
4. 检查语音是否和文本回复内容一致。
5. 检查数字人说话时是否有口型或动作变化。

通过标准：

- 能听到语音回复。
- 语音不是浏览器默认机械朗读，而是项目方配置的语音服务输出。
- 文本和语音内容基本一致。
- 语音播放过程中数字人有说话状态。

### 10.4 语音服务异常时的判断

如果没有声音，优先检查：

- `TTS_PROVIDER` 是否为 `dashscope` 或已正确配置 `gpt_sovits`
- `DASHSCOPE_API_KEY` 是否有效
- 网络是否能访问阿里云 DashScope
- DashScope 账号是否已开通对应语音模型且额度充足
- 如果使用 GPT-SoVITS，本地服务是否已启动，参考音频和提示文本是否配置完整
- 浏览器是否允许自动播放声音

专家只需记录异常现象，不需要自行修复语音服务。

## 11. 游客端功能验收清单

### 11.1 文本问答

测试问题：

```text
灵山大佛有什么特色？
```

通过标准：

- 能正常返回回答。
- 回答内容与景区知识相关。
- 简单问题回答不过度冗长。

### 11.2 路线推荐

测试问题：

```text
帮我推荐一条适合亲子的游览路线。
```

通过标准：

- 能给出游览顺序。
- 能说明推荐理由。
- 路线内容应结合知识库资料。

### 11.3 图片理解

操作步骤：

1. 上传一张景区相关图片。
2. 输入“这张图片里是什么，适合怎么玩？”
3. 查看回答。

通过标准：

- 系统可以接收图片。
- 回答中能结合图片内容进行说明。
- 不确定的图片内容不应被强行说成确定事实。

### 11.4 景点评论

操作步骤：

1. 查看左侧景点评论区域。
2. 切换不同景点。
3. 查看当前景点简介和评论列表。
4. 输入一条评论，可选择一张 JPG、PNG 或 WebP 景点实拍后发布。
5. 评论提交后会进入待审核状态，不会立即公开展示。
6. 管理员在后台审核通过后，刷新游客端查看图文评论。

通过标准：

- 可以切换景点。
- 评论区域内容随景点切换。
- 新评论可以出现在评论列表中。
- 评论和图片由后端本地持久化，刷新页面后仍然保留。
- 未审核或已拒绝的评论不会在游客端公开。
- 单张评论图片不能超过 8MB。

说明：如果后端不可访问，游客端会退回浏览器本地示例评论；以后台审核列表和刷新后的公开评论为准判断后端评论能力。

## 12. 管理后台功能验收清单

### 12.1 数据概览

通过标准：

- 指标卡正常显示。
- 图表区域正常显示。
- 页面布局无明显错位。

### 12.2 热门问答

操作步骤：

1. 在游客端连续提出几个问题。
2. 打开或刷新管理后台。
3. 查看热门问答区域。

通过标准：

- 热门问答以问题形式展示。
- 相似问题能归类计数。
- 问题次数能随游客端提问更新。

### 12.3 趋势图

通过标准：

- 趋势图展示平均停留时长、平均满意度等维度。
- 图表布局清晰，不遮挡其他区域。

### 12.4 游客图文评论审核与图片入库

操作步骤：

1. 在游客端选择景点，发布一条带图片的评论。
2. 打开管理后台底部“图文评论审核与景点图片入库”。
3. 在“待审核”筛选中找到评论，点击“通过”或“拒绝”。
4. 对已通过且包含图片的评论，点击“加入景点图库”。
5. 如需彻底移除评论及图片，点击“删除”。

通过标准：

- 新评论默认处于待审核状态。
- 审核通过后，游客端可以看到评论文字和游客实拍。
- 审核拒绝后，游客端不可见。
- 已通过的评论图片可以加入对应景点图库，并显示“已入库”。
- 删除评论时，原始上传图片和图库副本会一并清理。

## 13. 知识库验收清单

### 13.1 上传知识文件

支持格式：

- `.txt`
- `.md`
- `.docx`

通过标准：

- 文件可上传。
- 上传后显示生成的知识片段数量。
- 新条目可以在知识库列表中看到。

### 13.2 知识库问答验证

操作步骤：

1. 上传一份包含特定内容的测试资料。
2. 在游客端提问该资料中的内容。
3. 查看回答是否引用或基于该资料。

通过标准：

- 游客端回答能体现新上传资料。
- 回答不应明显偏离知识库内容。

## 14. 数字人形象管理验收清单

### 14.1 上传 Live2D 形象包

支持格式：

- `.zip`

形象包要求：

- zip 内必须包含 `.model3.json`
- 引用的纹理、moc3、物理、动作等资源必须完整
- 单个 zip 不能超过 80MB
- 解压后不能超过 240MB
- 当前游客端 Live2D 运行时支持到 moc3 v5

通过标准：

- 文件可上传。
- 上传后形象出现在形象库。
- 未手动启用前，不影响游客端当前形象。

### 14.2 编辑和启用形象

操作步骤：

1. 打开形象管理页面。
2. 选择一个自定义形象。
3. 修改名称、角色说明或显示参数。
4. 点击“保存参数”。
5. 点击“启用形象”。
6. 刷新游客端页面。

通过标准：

- 参数保存后仍然保留。
- 游客端加载当前启用形象。
- 内置形象不能删除。
- 自定义形象删除后，若原本处于启用状态，系统会回退到内置形象。

## 15. 常见问题

### 15.1 提示找不到 Python 3.12

安装 64 位 Python 3.12，安装时勾选 `Add python.exe to PATH`，然后重新运行 `安装环境.bat`。

### 15.2 提示 `.venv` 损坏或版本不符

关闭 Cyra 窗口后重新运行 `安装环境.bat`，脚本会自动清理并重建 `.venv`。

### 15.3 依赖下载失败

确认电脑可以联网访问 PyPI，然后重新运行 `安装环境.bat`。

### 15.4 后端端口被占用

现象：

```text
Backend port 8001 is already in use
```

处理方式：

- 关闭旧的 Cyra 后端窗口。
- 或结束占用 `8001` 的 Python 进程。
- 再重新运行 `启动Cyra.bat`。

### 15.5 前端端口不可用

现象：

```text
PermissionError: [WinError 10013]
```

处理方式：

- 换一个前端端口。
- 或关闭占用端口的程序。
- 以终端实际输出的访问地址为准。

### 15.6 WebGL unsupported

现象：

```text
WebGL unsupported in this browser
```

处理方式：

- 使用 Chrome 或 Edge 浏览器。
- 开启浏览器硬件加速。
- 避免使用不支持 WebGL 的浏览器环境。

### 15.7 页面提示服务没有连接成功

优先检查：

- 后端是否启动。
- `http://127.0.0.1:8001/api/health` 是否正常。
- `.env` 中大模型 Key 是否可用。
- 语音服务地址是否可访问。

### 15.8 上传 Live2D 形象失败

优先检查：

- 是否上传 `.zip` 文件。
- zip 内是否包含 `.model3.json`。
- `.model3.json` 引用的纹理、moc3、物理、动作文件是否完整。
- moc3 版本是否超过当前运行时支持范围。
- 文件大小是否超过限制。
