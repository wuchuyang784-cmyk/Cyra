# Cyra 灵山胜境 AI 数字人导览系统技术说明

本文档描述当前代码库已经实现的内容。当前版本包含游客端 Live2D 数字人导览页、园区管理后台和 FastAPI 后端服务；暂未接入景区资料 RAG 和持久化反馈。

## 1. 当前实现概览

已实现：

- 游客端 Live2D 数字人导览页：`http://127.0.0.1:5173/tourist.html`
- 园区管理后台：`http://127.0.0.1:5173/admin.html`
- FastAPI 后端：`http://127.0.0.1:8001`
- 管理后台数据接口：读取官方 Word/Excel 资料包并生成运营数据看板。
- LLM 流式文字对话：`POST /api/chat/stream`
- 本地 Whisper 语音输入：`POST /api/asr`
- 百炼 CosyVoice 语音合成：`POST /api/tts`
- 同源 TTS 音频代理：`GET /api/tts/audio`
- Live2D 数字人形象切换和背景上传。
- TTS 语音播放时驱动 Live2D 口型、头部和身体轻微讲解动作。当前口型优先采用百炼 CosyVoice 返回的字级时间戳驱动 `ParamA/I/U/E/O`，没有时间戳时才回退到 Web Audio 音量包络；说话时不启动 Mao Pro 自带嘴型 motion，避免语音口型和模型动作互相覆盖。

暂未实现：

- 景区资料 RAG 检索问答。
- 游客反馈写入后端。
- 管理后台知识库编辑后影响游客端回答。
- 独立演示入口页。

## 2. 技术栈

### 后端

- Python
- FastAPI：后端 API 服务
- Uvicorn：本地后端运行服务器
- Pydantic / pydantic-settings：请求模型和环境配置
- python-docx：解析官方 Word 资料包
- openpyxl：解析官方 Excel 游客行为数据
- urllib：调用 OpenAI-compatible LLM 接口，并作为百炼 CosyVoice HTTP 兜底路径
- dashscope SDK：通过 `dashscope.audio.tts_v2` 回调获取 CosyVoice 音频二进制和字级时间戳
- openai/Whisper：本地 `base` 模型语音识别，浏览器录音上传后转写为游客问题

### 前端

- 原生 HTML / CSS / JavaScript
- Pixi.js + pixi-live2d-display：加载 Live2D runtime 模型
- Web Audio API：解码 TTS 音频，按音频时钟采样字级时间戳并驱动口型
- MediaRecorder API：采集游客麦克风音频并上传到后端 ASR 接口
- Fetch API：调用后端 REST/流式接口

### AI 与语音能力

- LLM：百炼 OpenAI-compatible 接口，配置项为 `DASHSCOPE_API_KEY`、`DASHSCOPE_MODEL`。
- ASR：本地 openai/Whisper，默认 `WHISPER_MODEL=base`、`WHISPER_LANGUAGE=Chinese`、`WHISPER_DEVICE=cpu`。Whisper 需要 FFmpeg 解码浏览器音频，项目会优先使用系统 `ffmpeg`，如果没有安装，会尝试使用 `imageio-ffmpeg` 随 Python 环境提供的可执行文件。
- TTS：百炼 CosyVoice SDK 回调接口，开启 `word_timestamp_enabled` 获取字级时间戳，配置项为 `DASHSCOPE_TTS_MODEL`、`DASHSCOPE_TTS_VOICE`、`DASHSCOPE_TTS_WS_URL`。
- Live2D：当前接入 Mao Pro runtime 模型，目录为 `src/frontend/assets/live2d/mao_pro/`。

## 4. 本地运行方式

在项目根目录运行：

```powershell
python run_cyra_demo.py
```

启动后访问：

- 游客端：`http://127.0.0.1:5173/tourist.html`
- 管理后台：`http://127.0.0.1:5173/admin.html`
- 后端健康检查：`http://127.0.0.1:8001/api/health`

首次运行前安装依赖：

```powershell
pip install -r requirements.txt
```

## 5. 环境变量

后端读取 `src/backend/.env`。示例见 `src/backend/.env.example`。

必要配置：

```env
DASHSCOPE_API_KEY=你的百炼API Key
DASHSCOPE_MODEL=qwen-plus
DASHSCOPE_TTS_MODEL=cosyvoice-v3-flash
DASHSCOPE_TTS_VOICE=longanyang
WHISPER_MODEL=base
WHISPER_LANGUAGE=Chinese
WHISPER_DEVICE=cpu
```

不要把真实 `.env` 提交到公开仓库。

## 6. 前端页面说明

### 游客端

文件：`src/frontend/tourist.html`

核心能力：

- Live2D 数字人舞台。
- 数字人形象切换。
- 背景上传和白底恢复。
- 点击语音按钮录音，调用 `/api/asr` 将游客语音转写为文字提问。
- 流式文字对话。
- 按句调用百炼 TTS 并顺序播报。
- Web Audio 解码音频，按播放时钟采样百炼返回的字级时间戳。
- 按当前文字近似映射 Mao Pro 的 `ParamA/I/U/E/O`，驱动更接近发音的嘴型。
- 说话时清空 Mao Pro 的其他嘴型参数，避免 motion 曲线覆盖语音口型。
- 头部、身体轻微讲解动作。
- 景点快捷提问、路线推荐入口和前端反馈入口。

### 管理后台

文件：`src/frontend/admin.html`

已实现模块：

- 行为样本数
- 覆盖景区数
- 灵山相关访问量
- 平均满意度
- 平均停留时长
- 游客感受度报告
- 行业热门景区对比
- 游客年龄/性别画像
- 官方资料包知识条目展示

## 7. 后端接口说明

### 基础接口

```text
GET /api/health
```

### 对话接口

```text
POST /api/chat
POST /api/chat/stream
```

当前对话接口直接使用导游人设提示词调用 LLM，没有接入景区资料 RAG。LLM 不可用时会返回兜底导游回复。

### 语音接口

```text
POST /api/asr
POST /api/tts
GET /api/tts/audio?url=...
```

`/api/asr` 接收浏览器录制的音频文件，校验格式和大小后临时保存，调用本地 openai/Whisper `base` 模型转写文字，并返回 `text`、`language`、`duration`、`model`。浏览器默认录制的 WebM/Opus 需要 FFmpeg 支持，后端会尝试使用系统 FFmpeg 或 `imageio-ffmpeg` 兜底。

`/api/tts` 优先通过百炼 CosyVoice SDK 生成音频二进制和 `timestamps` 字级时间戳。后端会将音频临时缓存在内存里，并返回 `/api/tts/audio/{audio_id}` 作为同源播放路径。若 SDK 不可用，会回退到 HTTP 临时音频 URL 代理路径，但可能没有字级时间戳。

### 管理后台接口

```text
GET /api/admin/knowledge
GET /api/admin/analytics/overview
GET /api/admin/analytics/report
```

## 8. 当前问答与播报流程

```text
游客输入文字问题或点击语音按钮提问
  -> 语音提问先调用 /api/asr 转写为文字
  -> 前端调用 /api/chat/stream
  -> 后端使用导游人设调用 LLM
  -> 前端流式显示文字
  -> 前端按标点拆分短句
  -> 每个短句调用 /api/tts
  -> 后端通过百炼 CosyVoice SDK 回调获取音频和字级时间戳
  -> 前端通过 /api/tts/audio/{audio_id} 播放同源缓存音频
  -> Web Audio 解码音频并按同一音频时钟采样 timestamps
  -> 前端驱动 Live2D 的 ParamA/I/U/E/O 和讲解动作
```

## 9. 后续开发建议

优先级从高到低：

1. 将当前字级时间戳口型升级为更精细的拼音/音素级 viseme 映射。
2. 优化 ASR：增加静音检测、录音时长提示和识别耗时监控。
3. 接入景区资料 RAG，提高回答准确性。
4. 将游客反馈写入后端，并联动管理后台统计。
5. 增加二维码访问页。
6. 增加 SQLite 持久化。
7. 准备标准问答测试集和演示脚本。
